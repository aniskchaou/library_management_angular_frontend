The Notice module is used to create, manage, and distribute notices within the library. This includes notices for library closures, maintenance, events, and other important information. The module allows customization of notice content, scheduling, and distribution methods.

Fields and Descriptions

Title:

  • Description: The title of the notice.
  • Usage: Enter a brief, descriptive title for the notice.
  • Example: "Library Closure Notice"
  • Validation: Must be a valid string.

Content Template:

  • Description: The template or body content of the notice, which may include placeholders for dynamic content.
  • Usage: Enter the main content of the notice, including placeholders like [receiverName], [startDate], and [endDate] for personalized details.
  • Example: "Dear [receiverName], please be informed that the library will be closed for maintenance from [startDate] to [endDate]. We apologize for any inconvenience caused."
  • Validation: Must be a valid string with placeholders replaced by actual data when the notice is issued.

Start Date:

  • Description: The date when the notice period begins.
  • Usage: Enter the start date of the notice validity in the format yyyy-mm-dd.
  • Example: "2024-06-15"
  • Validation: Must be a valid date format (yyyy-mm-dd).

End Date:

  • Description: The date when the notice period ends.
  • Usage: Enter the end date of the notice validity in the format yyyy-mm-dd.
  • Example: "2024-06-20"
  • Validation: Must be a valid date format (yyyy-mm-dd).

Author:

  • Description: The person or entity who created the notice.
  • Usage: Enter the name of the author or department responsible for the notice.
  • Example: "Library Administration"
  • Validation: Must be a valid string.

Status:

  • Description: The current status of the notice.
  • Usage: Select the status of the notice from the available options (e.g., Published).
  • Example: "Published"
  • Validation: Must be selected from predefined status options (e.g., Draft, Published).

Notification Methods:

  • Description: The methods through which the notice will be communicated.
  • Usage: Select the notification methods to be used (e.g., SMS, Email, Member Portal).
  • Example: "SMS, Email, Member Portal"
  • Validation: Must be selected from available communication methods.

Receiver:

  • Description: The recipient or audience of the notice.
  • Usage: Enter the identifier or name of the recipient, such as a member ID or group name.
  • Example: "member123"
  • Validation: Must be a valid recipient identifier.

Object:

  • Description: The subject or main topic of the notice.
  • Usage: Enter the main topic or subject matter of the notice.
  • Example: "Library Closure"
  • Validation: Must be a valid string.

Type:

  • Description: The category or type of notice.
  • Usage: Enter or select the type of notice (e.g., Scheduled Maintenance).
  • Example: "Scheduled Maintenance"
  • Validation: Must be selected from predefined notice types.

Importance:

  • Description: The importance level of the notice.
  • Usage: Specify the level of importance (e.g., High, Medium, Low).
  • Example: "High"
  • Validation: Must be selected from predefined importance levels.
